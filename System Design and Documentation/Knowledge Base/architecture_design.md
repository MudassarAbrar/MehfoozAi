The module is a monorepo-style single package (`MehfoozAi/`) that ships both the Vite SPA and an Express server from one entry point.

- Server layer (`server.ts`): A single Express app that mounts security middleware (helmet, rate limiting via `express-rate-limit`, input sanitization), then registers API routes under `/api/`. Routes are grouped by concern: orchestration (`/api/orchestrate`, `/confirm`, `/cancel`, `/conversations*`), channel recommendation (`/api/recommend-channel`), complaint handoff (`/api/mock-handoff`, `/api/complaint-handoff`, `/api/complaints/send-email`), and health/status endpoints. Authentication is pluggable via `supabaseAuthOptional` / `requireSupabaseAuth` middleware; when no `GEMINI_API_KEY` is set the server falls back to a deterministic rule engine and local corpus. The Gemini client is lazily instantiated per request scope to avoid cold-start overhead on serverless.
- Frontend layer (`src/`): `App.tsx` is the root component that owns global state (auth, active tab, stealth lock/unlock via Weather cover) and renders one of many tab-based views under `components/` (HomeDashboard, SafeNavigation, LegalAssistant, IncidentVault, ComplaintBuilder, TrackingDashboard, SupportDirectory, etc.). Shared UI primitives live in `components/ui/` (shadcn-derived badge/button/card/primitives) and cross-cutting widgets in `components/common/` (OfflineIndicator, PWAInstallButton, OpenStreetMapViewer). Data files in `data/` hold static support directories and the offline legal corpus used when the backend LLM is unavailable.
- State & services: `utils/` holds all cross-cutting logic — `auth.ts` (Supabase/local session), `chatState.tsx` (ChatStateProvider context), `hybridRetriever.ts` (Gemini embeddings + keyword scoring), `offlineEmergencyCache.ts` (pre-cached directory/legal articles), `pdfExport.ts`, `crypto.ts` (client-side AES-GCM vault), and `agentClient.ts` (calls server orchestrator endpoints). `hooks/` exposes `useOnlineStatus` and `usePWAInstall`. `services/osmService.ts` wraps OpenStreetMap/Nominatim calls.
- Types: All shared interfaces (`UserProfile`, `ComplaintDraft`, `AgentResponse`, `LegalSourceCitation`, `ActiveTab`, etc.) are centralized in `src/types.ts` and imported everywhere rather than redefined inline.
- Dependency direction: Components → utils/hooks → services/data; the server imports from `./server/*` (not shown in scope) and from `./src/utils/hybridRetriever.js`; the frontend never imports server code directly. Build-time bundling uses esbuild to compile `server.ts` into `dist/server.cjs` while Vite builds the SPA separately.
